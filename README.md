# LJ640U34 EL 显示器驱动

基于 **Sharp LJ64EU34**（640×400 单色琥珀 EL 显示屏）的显示驱动与上位机项目。
本项目为**个人非商业粉丝自制**，与 Glitch Productions 无关。

## 硬件概览

- **面板**：Sharp LJ64EU34（640×400 单色 EL；5 路 TTL + 5V/12V 双电源）
- **主控**：RP2040-Zero（3.3V）+ LJ245A 电平转换（VCA3.3 / VCB5V / 共地 / OE=GND / DIR=5V）
- **信号接线**：GP10→CK0、GP11→Din0、GP12→Din1、GP13→H.D、GP14→V.D
- **外设**：GP7 单键、GP8 12V 高边开关、GP6 风扇 PWM（25kHz）、GP16 WS2812

## 使用

1. **固件**：用 arduino-pico core 6.0.0 打开 `LJ640U34_solver_dualcore_v6.01/` 并烧录。
2. **上位机**：浏览器打开 `usb_el_display_single_v6.html`，连接串口后选择推流内容类型。

## 版本记录

### v6.01（2026-10-08，真机复验通过）—— 修复差分帧导致的画面前后交替闪烁

- **症状**：推流时画面在两代内容之间来回翻、"不停闪烁打架"。
  **稀疏画面最明显**（只有几个数字在跳那种）；密集画面或整屏刷新时反而看不出来。
- **根因**：`commitFrame()` 每提交一帧就乒乓交换 `drawIdx` / `dispIdx`，
  而**差分帧只写变化行，"保留"的其余行其实是「两帧前」的内容**
  ⇒ 屏上显示 = 两帧前画面 + 本帧变化行。
  （整帧 / RLE 本来就是 `memcpy` 全量覆盖，不受影响 —— 这也是它长期没暴露的原因：
  此前只在真机上验过静态棋盘全帧，差分路径没肉眼验收过。）
- **修法**：差分提交前先 `waitSwapDone()`，再把「正在显示的那一帧」整块拷进绘制缓冲。
- **代价**：+32 KB `memcpy`/帧（≈60 µs @133 MHz），**带宽完全不变**（仍是几 KB 的行差分），
  内存不增加。且**自校正** —— 重连 / 4 s 超时回本地页 / 切页之后都自动正确，
  上位机侧无需保存任何状态。
- 软件复现量化：错像素占**点亮像素的 33%**（稀疏段）、6.9%（密集段）、0.4%（整屏刷新段）。

### v6（2026-08-27 定稿）

- 风扇开环调速：GP6 PWM 25kHz，按内容档位查表输出占空比，每档占空比存 flash。
- 协议扩展：`'V'` + 7 字节写档位、`'R'` 回传设置、`'T'` + 1 字节设推流内容类型。
- 更早改动（v2~v5）见固件文件头里的完整记录。
